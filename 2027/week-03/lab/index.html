W03-Lab

สร้างต้นแบบขอรับบริการในมหาวิทยาลัย

ก่อนเริ่มต้น

[ลิงก์ Edpuzzle — ผู้สอนเพิ่มภายหลัง]

สร้างต้นแบบ Campus Help ที่เลือกบริการ ดูรายละเอียด และแสดงข้อความยืนยันแบบจำลองได้ คุณจะตรวจพฤติกรรมกับ acceptance criteria และปรับตามการลองใช้ของเพื่อน ยังไม่ส่งคำขอจริงไปยังมหาวิทยาลัย

[ภาพตัวอย่างแอป — ผู้สอนเพิ่มภายหลัง]

  1. ใช้ Xcode บน Mac หรือ Swift Playgrounds บน iPad ที่สร้าง App ได้ และพื้นฐาน State จาก Week 02
  2. ใช้ข้อมูลสมมติ ไม่ใช้ชื่อหรือข้อมูลติดต่อของผู้ใช้จริง เตรียมแอปเอกสารสำหรับรวมภาพเป็น PDF
  3. กำหนดเกณฑ์สามข้อ: เปิดรายละเอียดได้ ย้อนกลับได้ และยืนยันแล้วแสดงชื่อบริการที่เลือก

ภารกิจ

1. สร้างโปรเจกต์และหน้ารายการ 15 นาที

  1. สร้าง iOS App ชื่อ CampusHelp เลือก SwiftUI/Swift ใน Xcode; บน iPad เลือก App ใหม่และตั้งชื่อเดียวกัน เก็บไฟล์ App เดิมไว้
  2. ใน ContentView เพิ่ม state ก่อน body แล้วใส่ VStack ตามตัวอย่าง โดยลบเฉพาะเนื้อหา body เดิม

ContentView.swift

// Inside ContentView, before body:
@State private var showDetail = false
@State private var requested = false

// Inside body:
VStack(spacing: 16) {
    Text("Campus Help").font(.title)
    Button("Library help") { showDetail = true }
}
.padding()

ตรวจผล / แก้ปัญหา: Run แล้วเห็นชื่อแอปและปุ่ม Library help ถ้า state อยู่นอก struct ให้ย้ายเข้าไปก่อน body

เก็บภาพที่ 1: หน้ารายการก่อนเปิดรายละเอียด

2. เพิ่มรายละเอียดและเส้นทางกลับ 20 นาที

  1. ภายใน VStack แทนปุ่มเดิมด้วย if ด้านล่าง คง Text ชื่อแอปไว้
  2. เลือกคำอธิบายบริการให้ชัดว่าต้นแบบช่วยใคร เช่น ผู้ใช้ที่หาช่องทางขอความช่วยเหลือในห้องสมุด
  3. ทดสอบเปิดรายละเอียดและกด Back ให้กลับหน้ารายการ

ContentView.swift

if showDetail {
    Text("Library help")
    Text("Ask about library services.")
    Button("Back") { showDetail = false }
} else {
    Button("Library help") { showDetail = true }
}

ตรวจผล / แก้ปัญหา: เห็นปุ่ม Back เฉพาะหน้ารายละเอียด หากกดแล้วไม่กลับตรวจการกำหนด showDetail = false

เก็บภาพที่ 2: หน้ารายละเอียดที่มีคำอธิบายและปุ่ม Back

3. เพิ่มการยืนยันจำลอง 15 นาที

  1. เพิ่มปุ่มและข้อความด้านล่างในแขนง showDetail หลังคำอธิบายและก่อน Back
  2. ใน action ของปุ่ม Library help กำหนด requested = false ก่อน showDetail = true เพื่อเริ่มการดูใหม่
  3. ลองยืนยัน กลับ แล้วเปิดใหม่ สังเกตว่าเป็นสถานะใหม่ ไม่มีคำขอจริงถูกส่ง

ContentView.swift

Button("Request help") { requested = true }
if requested {
    Text("Library help requested — simulation")
}

ตรวจผล / แก้ปัญหา: กดแล้วเห็นชื่อบริการและคำว่า simulation หากข้อความค้างหลังเปิดใหม่ ให้ตรวจบรรทัด reset ในปุ่มเปิดรายละเอียด

เก็บภาพที่ 3: ข้อความยืนยัน Library help พร้อมคำว่า simulation

4. ตรวจข้อผิดพลาดและลองใช้กับเพื่อน 25 นาที

  1. จงใจนำ requested = false ออกจากปุ่มเปิดรายละเอียดชั่วคราว ยืนยันแล้วกลับและเปิดใหม่เพื่อดูข้อความเก่าค้าง จากนั้นใส่บรรทัดกลับคืน
  2. ให้เพื่อนลองค้นหาบริการ เปิดรายละเอียด และยืนยันโดยคุณไม่บอกตำแหน่งปุ่ม สังเกตจุดลังเลแล้วปรับข้อความหนึ่งจุด
  3. ตรวจเกณฑ์สามข้ออีกครั้ง รวมถึงตัวอักษรใหญ่และการอ่านปุ่มด้วย VoiceOver ถ้าข้อความยาวถูกตัดให้ครอบ VStack ด้วย ScrollView
  4. เก็บภาพหลังซ่อมและปรับคำ ไม่ต้องส่งบันทึกการสัมภาษณ์เพิ่ม

ตรวจผล / แก้ปัญหา: เปิดใหม่แล้วไม่มีข้อความยืนยันเก่า ปุ่มมีชื่อบอกการกระทำและข้อความไม่ถูกตัด

เก็บภาพที่ 4: หน้ารายละเอียดหลังเปิดใหม่ที่ซ่อม reset แล้วและมีคำอธิบายที่ปรับปรุง
