ภารกิจ

1. กำหนด state และ UI 20 นาที

  1. เพิ่ม enum LoadState นอก ContentView ตามตัวอย่าง
  2. ใน ContentView เพิ่ม @State private var state = LoadState.idle กับ @State private var loading = false
  3. แทน Ready to load ด้วย switch state: idle แสดง Choose a source, loading ใช้ ProgressView, empty แสดง No notices, loaded ใช้ List(items) และ failed แสดง message
  4. แสดง Text ของ source.rawValue เสมอเพื่อไม่สับสน fixture กับ live

ContentView.swift — ก่อน struct ContentView

enum LoadState {
    case idle, loading, empty
    case loaded([Notice])
    case failed(String)
}

ตรวจผล / แก้ปัญหา: ทุก case มีผลลัพธ์ที่เห็นได้ หาก switch ไม่ครบ compiler จะบอก case ที่ขาด

เก็บภาพที่ 1: หน้าจอเริ่มต้นที่เห็น source และ idle

2. เชื่อม async load และป้องกันซ้ำ 20 นาที

  1. เพิ่มเมธอด load ตาม excerpt ภายใน ContentView หลัง body
  2. เพิ่ม Button("Load / Retry") { Task { await load() } } และ .disabled(loading)
  3. ต่อ .disabled(loading) ให้ Picker ด้วย เพื่อคง source ของ request ที่กำลังทำงาน
  4. ทดสอบ fixture และกดซ้ำระหว่าง loading

ContentView.swift — เมธอดภายใน struct หลัง body

@MainActor private func load() async {
    guard !loading else { return }
    loading = true
    state = .loading
    defer { loading = false }
    do {
        let items = try await NoticeService().fetch(source)
        try Task.checkCancellation()
        state = items.isEmpty ? .empty : .loaded(items)
    } catch is CancellationError {
        state = .idle
    } catch {
        state = .failed("Could not load. Check source and retry.")
    }
}

ตรวจผล / แก้ปัญหา: fixture แสดงประกาศหลัง loading และไม่เริ่มงานซ้อน หาก spinner ค้างตรวจ defer และ catch ทุกเส้นทาง

เก็บภาพที่ 2: ผล loaded ของ fixture พร้อมชื่อ source

3. ตรวจ empty และข้อมูลผิด 20 นาที

  1. เลือก empty แล้ว Load ต้องแสดง No notices ไม่ใช่ error
  2. เลือก malformed แล้ว Load ต้องออกจาก loading เป็น failure ตรวจ NoticeService ว่า JSON ขาด title
  3. เลือก failure แล้ว Load ให้เห็นทาง retry โดยไม่ปิดแอป
  4. ปรับข้อความ failure ให้ช่วยแก้ source หรือเครือข่าย ไม่ล้าง state โดยแสดงว่าสำเร็จ

ตรวจผล / แก้ปัญหา: empty ต่างจาก error และทุกกรณีทำให้ปุ่มกลับมากดได้

เก็บภาพที่ 3: failure จาก malformed ที่มีปุ่ม Retry ใช้งานได้

4. ทดสอบ live และ fallback 15 นาที

  1. เลือก live แล้ว Load เมื่อมีอินเทอร์เน็ต ต้องอ่าน synthetic JSON ของเว็บไซต์คอร์ส
  2. เมื่อ live ใช้ไม่ได้ให้เลือก fixture อย่างชัดเจนและ Load ต้องยังสาธิตพฤติกรรมได้ โดยไม่อ้างว่าเชื่อมบริการสำเร็จ
  3. บันทึกภาพ empty เพิ่มในหน้าเดียวกับคำบรรยายก่อนกลับไป live หรือ fixture สุดท้ายตามภาพที่ขอ
  4. ตรวจข้อความใหญ่และ VoiceOver ของสถานะ loading/error

ตรวจผล / แก้ปัญหา: source label ตรงกับเส้นทางจริง หาก live ไม่ผ่านแต่ fixture ผ่าน ให้ตรวจ URL/HTTP แยกจาก decoder

เก็บภาพที่ 4: empty state ที่แสดง No notices และ source empty
