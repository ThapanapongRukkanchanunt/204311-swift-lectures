ก่อนเริ่มต้น

เพิ่ม SwiftData ให้คำขอ Campus Help สร้าง อ่าน แก้ไข และลบได้ พร้อมตรวจว่าข้อมูลอยู่ข้ามการเปิดแอป

[ภาพตัวอย่างแอป — ผู้สอนเพิ่มภายหลัง]

  1. ใช้ SwiftData บน toolchain ที่รองรับ iOS/iPadOS 17+ และ Swift 5.9+ ให้ผู้สอนยืนยันเครื่องก่อนเริ่ม
  2. เริ่มจาก starter ใหม่เพื่อไม่เปลี่ยน schema ของโปรเจกต์เดิม ใช้ข้อมูลสมมติเท่านั้น
  3. เก็บ App entry ที่โปรเจกต์สร้างไว้และเตรียมแก้ container ที่ไฟล์นั้น

เตรียมโปรเจกต์

ดาวน์โหลด catch-up starter Week 09 แล้วแตกไฟล์ สร้างโปรเจกต์ SwiftUI App ใหม่ใน Xcode หรือ App ใหม่ใน Swift Playgrounds เก็บ App entry เดิมไว้ เพิ่มไฟล์ Swift ตาม README และแทนเฉพาะ ContentView.swift ของโปรเจกต์ใหม่ Run ให้ผ่านก่อนแก้ตามภารกิจ ไม่ทับโปรเจกต์เดิม เห็น Campus Help storage checkpoint ก่อนเพิ่ม SwiftData

ภารกิจ

1. เพิ่ม model และ container 20 นาที

  1. สร้าง ServiceRequest.swift ตามตัวอย่าง
  2. ในไฟล์ App ของโปรเจกต์เพิ่ม import SwiftData และต่อ .modelContainer(for: ServiceRequest.self) กับ WindowGroup ที่เปิด ContentView
  3. Run ให้ผ่านก่อนเพิ่ม query หาก preview error ให้ทดสอบด้วย Run และตรวจ container ของ preview แยก

ServiceRequest.swift — ไฟล์ใหม่

import SwiftData
@Model
final class ServiceRequest {
    var title: String
    var isOpen: Bool
    init(title: String, isOpen: Bool = true) {
        self.title = title
        self.isOpen = isOpen
    }
}

ตรวจผล / แก้ปัญหา: แอปเปิดได้พร้อม container ที่ตรงกับชนิด model อย่าใส่ inMemory: true ในแอปที่ใช้ตรวจ persistence

เก็บภาพที่ 1: โค้ด App ที่กำหนด modelContainer และชนิด model

2. อ่านและเพิ่มคำขอ 20 นาที

  1. ใน ContentView เพิ่ม import SwiftData, @Environment(\.modelContext) private var context, @Query(sort: \ServiceRequest.title) private var requests: [ServiceRequest], State draft และ State message แบบ String
  2. ใน body ใช้ VStack ที่มี TextField ผูก draft ปุ่ม Add และ List(requests) ที่แสดง title รวมถึง Text(message)
  3. ให้ Add trim draft ตรวจไม่ว่าง แล้วใช้ insert/save ตามตัวอย่าง ถ้าพลาดคง draft ไว้

ContentView.swift — action ของ Add หลังตรวจ draft

let item = ServiceRequest(title: draft)
context.insert(item)
do {
    try context.save()
    draft = ""
    message = "Saved"
} catch {
    context.rollback()
    message = "Could not save. Try again."
}

ตรวจผล / แก้ปัญหา: เพิ่มคำขอได้หนึ่งรายการต่อการกดสำเร็จ หากเกิดซ้ำตรวจว่าไม่ได้ insert ใน body หรือ onAppear

เก็บภาพที่ 2: รายการหลัง Add สำเร็จพร้อมข้อความ Saved

3. แก้ไขและลบ record เดิม 20 นาที

  1. ใน row ให้ใช้ TextField("Title", text: Binding(get: { item.title }, set: { item.title = $0 })) และปุ่ม Save edit ที่ try context.save() พร้อม catch แสดง message และ rollback
  2. เพิ่มปุ่ม Toggle status ที่ item.isOpen.toggle() แล้ว save พร้อม error handling แบบเดียวกัน
  3. เพิ่ม Remove สำหรับข้อมูลฝึกของแถวนั้น ใช้ context.delete(item) แล้ว save โดยแสดงชื่อที่จะลบให้ชัด
  4. เลือกคำขอหนึ่งรายการแก้ชื่อและปิดสถานะ อีกหนึ่งรายการลบ

ตรวจผล / แก้ปัญหา: update ไม่สร้าง record ใหม่และลบเฉพาะ model ที่เลือก หากชื่อเปลี่ยนแต่เปิดใหม่ไม่อยู่ตรวจ save/error

เก็บภาพที่ 3: รายการที่แก้ชื่อและสถานะแล้วโดยอีก record ถูกลบ

4. ตรวจ relaunch และการ seed ซ้ำ 15 นาที

  1. สร้างคำขอสมมติสองรายการ แก้หนึ่งรายการและลบอีกหนึ่ง จากนั้นหยุดแอปและ Run ใหม่บน Mac; iPad ปิดแอปที่ run แล้วเปิดใหม่ตามเครื่องมือที่ใช้
  2. ตรวจจำนวน ชื่อ และสถานะเทียบกับก่อนปิด ไม่ใช้เพียงการปิด preview
  3. เปิดหน้าจอซ้ำและตรวจว่าไม่มี fixture เพิ่มเอง หากมีให้ย้ายการสร้างออกจาก onAppear
  4. หาก save error อย่าลบแอปเพื่อซ่อนปัญหา ให้ตรวจ message และเก็บข้อมูลฝึกแยกไว้

ตรวจผล / แก้ปัญหา: เหลือเฉพาะรายการที่ควรอยู่พร้อมค่าที่แก้หลังเปิดใหม่

เก็บภาพที่ 4: หลัง relaunch เห็นจำนวน ชื่อ และสถานะตามที่คาด
