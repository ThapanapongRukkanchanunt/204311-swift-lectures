W04-Lab

จัดหน้าบริการให้ใช้ได้กับข้อความขนาดใหญ่

ก่อนเริ่มต้น

[ลิงก์ Edpuzzle — ผู้สอนเพิ่มภายหลัง]

สร้างหน้าบริการ Campus Help ด้วย ServiceCard ที่ใช้ซ้ำได้ แล้วตรวจชื่อยาว ขนาดอักษรใหญ่ และชื่อที่ VoiceOver อ่าน

[ภาพตัวอย่างแอป — ผู้สอนเพิ่มภายหลัง]

  1. Xcode บน Mac หรือ Swift Playgrounds บน iPad และความรู้ VStack / Text
  2. สร้างโปรเจกต์ใหม่ CampusHelpLayout เพื่อเก็บ prototype Week 3 ไว้โดยไม่ทับ ใช้ข้อมูลบริการสมมติ
  3. เตรียม Simulator สองขนาดบน Mac; บน iPad ใช้แนวตั้งและแนวนอน พร้อมการตั้งค่าขนาดข้อความ

ภารกิจ

1. สร้างหน้าจอและข้อมูลตัวอย่าง 15 นาที

  1. สร้าง SwiftUI App ใหม่ เก็บ App entry เดิม แล้วใช้ ScrollView ครอบ VStack ใน ContentView
  2. ใส่ Text ชื่อ Campus Help และข้อความบริการสองรายการ: Library help กับ Student support
  3. ใส่ padding รอบ VStack และ Run

ContentView.swift — แทนเนื้อหาภายใน body

ScrollView {
    VStack(alignment: .leading, spacing: 16) {
        Text("Campus Help").font(.title)
        Text("Library help")
        Text("Student support")
    }.padding()
}

ตรวจผล / แก้ปัญหา: เห็นข้อมูลสองบริการและเลื่อนได้เมื่อข้อความยาว หากหน้าว่างตรวจว่า App เปิด ContentView

เก็บภาพที่ 1: หน้าบริการเริ่มต้นที่เห็นข้อมูลสองรายการ

2. แยก ServiceCard 20 นาที

  1. เพิ่ม ServiceCard หลังวงเล็บปิด ContentView ตามตัวอย่าง
  2. แทน Text ของบริการสองรายการด้วย ServiceCard(title:detail:) ส่งชื่อและคำอธิบายของแต่ละบริการ
  3. ให้คำอธิบายหนึ่งรายการยาวอย่างน้อยสองประโยค ไม่ย่อข้อมูลเพื่อให้พอดี

ContentView.swift — หลัง struct ContentView

struct ServiceCard: View {
    let title: String
    let detail: String
    var body: some View {
        VStack(alignment: .leading, spacing: 8) {
            Text(title).font(.headline)
            Text(detail).font(.body)
        }
        .frame(maxWidth: .infinity, alignment: .leading)
        .padding()
        .background(.thinMaterial)
        .clipShape(RoundedRectangle(cornerRadius: 16))
    }
}

ตรวจผล / แก้ปัญหา: ทั้งสองการ์ดใช้โครงสร้างเดียวกันแต่เนื้อหาต่างกัน หากพบชื่อชนิดซ้ำตรวจว่าเพิ่ม struct เพียงครั้งเดียว

เก็บภาพที่ 2: สอง ServiceCard ที่มีชื่อและคำอธิบายต่างกัน

3. ทดสอบ modifier และซ่อมข้อความที่ถูกตัด 20 นาที

  1. จงใจใส่ .frame(height: 60) ต่อท้าย VStack ภายใน ServiceCard แล้วเพิ่มขนาดข้อความจาก Settings หรือ Simulator Environment Overrides สังเกตการล้น
  2. นำ frame(height:) ออก คง semantic fonts และ ScrollView
  3. สลับ padding กับ background แล้วเปรียบเทียบพื้นที่ที่มีสี เลือกแบบที่อธิบายเหตุผลได้

ตรวจผล / แก้ปัญหา: คำอธิบายยาวอ่านครบและเลื่อนได้โดยไม่ลดขนาดฟอนต์เพื่อซ่อนปัญหา

เก็บภาพที่ 3: หน้าจอหลังซ่อมที่ใช้ขนาดข้อความใหญ่และเห็นคำอธิบายครบ

4. ตรวจการอ่านและสองขนาดหน้าจอ 20 นาที

  1. เพิ่ม Text("Open") หรือ Text("Closed") ในการ์ดเพื่อบอกสถานะโดยไม่พึ่งสี
  2. ทดสอบ VoiceOver โดยฟังชื่อบริการก่อนรายละเอียด ถ้าเพิ่มไอคอนตกแต่งให้ใส่ .accessibilityHidden(true)
  3. Mac: ทดสอบ Simulator อีกขนาด; iPad: หมุนแนวตั้ง/แนวนอน ตรวจลำดับข้อมูล ปุ่มหรือข้อความไม่ซ้อนกัน
  4. คงความสูงตามเนื้อหาและบันทึกโปรเจกต์นี้เป็นฐานสำหรับ Week 5

ตรวจผล / แก้ปัญหา: สถานะอ่านได้โดยไม่เห็นสีและข้อมูลไม่ล้นในสองสภาพหน้าจอ ภาพยืนยัน layout ส่วน VoiceOver ต้องตรวจด้วยการฟังจริง

เก็บภาพที่ 4: อีกขนาดหรืออีกแนวหน้าจอที่ข้อมูลยังอ่านได้
