  3. ไม่มีบัญชีภายนอกหรือข้อมูลส่วนตัว

เตรียมโปรเจกต์

ดาวน์โหลด catch-up starter Week 08 แล้วแตกไฟล์ สร้างโปรเจกต์ SwiftUI App ใหม่ใน Xcode หรือ App ใหม่ใน Swift Playgrounds เก็บ App entry เดิมไว้ เพิ่มไฟล์ Swift ตาม README และแทนเฉพาะ ContentView.swift ของโปรเจกต์ใหม่ Run ให้ผ่านก่อนแก้ตามภารกิจ ไม่ทับโปรเจกต์เดิม Run แล้วคิวเริ่ม 0 เพิ่มได้ถึง 3 และลดไม่ต่ำกว่า 0

ภารกิจ

1. กำหนด invariant และสร้าง model 20 นาที

  1. เพิ่มไฟล์ QueueModel.swift และ import Observation
  2. สร้าง @Observable final class QueueModel มี private(set) var count = 0 กับ let capacity = 3
  3. เพิ่ม join ตาม excerpt และ leave ที่ใช้ count = max(0, count - 1) เลือกชื่อเมธอดได้แต่ต้องรักษา invariant

QueueModel.swift — ภายใน QueueModel

func join() -> Bool {
    guard count < capacity else { return false }
    count += 1
    return true
}

ตรวจผล / แก้ปัญหา: model ป้องกัน count ทั้งขอบล่างและขอบบน หาก macro ไม่รองรับให้ตรวจ toolchain กับผู้สอน ไม่เปลี่ยนชนิดจนตัวอย่างคนละแนวทาง

เก็บภาพที่ 1: โค้ด model ที่เห็น invariant ผ่านเมธอดและ private(set)

2. ให้ parent เป็นเจ้าของ instance 15 นาที

  1. ใน ContentView แทน @State count ด้วย @State private var queue = QueueModel()
  2. เปลี่ยน Text ให้อ่าน queue.count และเปลี่ยนปุ่มให้เรียก queue.join() / queue.leave()
  3. เพิ่ม @State message แล้วให้ Join ตั้ง message ตามผล Bool จาก model และแสดง Text(message)

ตรวจผล / แก้ปัญหา: กดครั้งที่สี่แล้วจำนวนไม่เกิน 3 และมีข้อความ Full หากยังแก้ count โดยตรงให้เปลี่ยน caller ทุกจุด

เก็บภาพที่ 2: จำนวนเต็มความจุและข้อความ Full

3. เชื่อมสอง view กับ model เดียว 20 นาที

  1. เพิ่ม QueueSummary ตามตัวอย่าง แล้วให้ ContentView ใช้ QueueSummary(queue: queue)
  2. แยกปุ่ม Join/Leave เป็น QueueControls ที่รับ let queue: QueueModel และมี State message ของตนเอง
  3. ส่ง queue เดิมให้ QueueSummary และ QueueControls ห้ามสร้าง QueueModel() ใหม่ในลูก

ContentView.swift — หลัง struct ContentView

struct QueueSummary: View {
    let queue: QueueModel
    var body: some View {
        Text("Waiting: \(queue.count)")
        Text("Remaining: \(queue.capacity - queue.count)")
    }
}

ตรวจผล / แก้ปัญหา: กดปุ่มในลูกแล้ว summary เปลี่ยนตรงกัน ถ้าไม่ตรงให้ตรวจว่าใช้ instance เดียว

เก็บภาพที่ 3: สองส่วน summary และ controls ที่แสดงผลของการกดเดียวกัน

4. ตรวจ refactor และเส้นทางผิด 20 นาที

  1. กด Leave ตอน 0 แล้ว Join สี่ครั้ง จากนั้น Leave จน 0 อีกครั้ง ตรวจขอบเขตทุกช่วง
  2. จงใจสร้าง QueueModel() ใน QueueSummary แทนการรับค่า สังเกตว่าข้อมูลไม่ตรง แล้วคืน let queue ที่รับจาก parent
  3. เพิ่มปุ่ม Check model ในหน้าทดลอง ใช้ QueueModel instance ใหม่ เรียก join สี่ครั้งและ leave สี่ครั้ง แล้วแสดง PASS เมื่อครั้งที่สี่ถูกปฏิเสธและสุดท้ายเป็น 0 ไม่แก้ queue จริง
  4. ตรวจ large text และชื่อปุ่มด้วย VoiceOver

ตรวจผล / แก้ปัญหา: model checks ไม่ขึ้นกับ UI queue และแสดง PASS หลังซ่อม หากทดสอบเปลี่ยนคิวจริงแสดงว่าใช้ instance ผิด

เก็บภาพที่ 4: ผล Check model เป็น PASS พร้อมคิวจริงที่ยังถูกต้อง
