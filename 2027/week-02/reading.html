01 · The framework contract 05 / 23

Inversion of Control

  • An ordinary call starts when application code chooses to invoke a function.
  • For a callback, application code supplies behavior and the framework invokes it later.
  • Developers choose the response. The framework coordinates when it runs.

Discuss / predictWhat initiates an app launch, a button activation, or a timer event?

01 · State and transitions 09 / 23

State Is Memory That Affects Output

  • State: information that changes and affects output.
  • Event: something the app responds to.
  • Transition: old state + event → new state.
  • Derived output: calculated from current facts.

waiting: 3 + joinQueue → waiting: 4

Discuss / predictClassify a tap, battery percentage, a “low battery” label and a capacity rule.

A turnstile makes state and events visible. Follow one event at a time.

01 · Read and write state 10 / 23

A Minimal Stateful View

Swift / SwiftUI excerpt

struct QueueView: View {
    @State private var waiting = 3

    var body: some View {
        VStack {
            Text("Waiting: \(waiting)")
            Button("Join queue") { waiting += 1 }
        }
    }
}

Find: owned state · state read · action closure · state write

02 · Declarative updates 15 / 23

Recompute Is Not Relaunch

  • The application remains running.
  • SwiftUI may reevaluate descriptions that read changed data.
  • A description states what the interface should show now.
  • SwiftUI determines the necessary presentation updates.

Discuss / predictWhy should body describe output instead of changing the state it reads?

Do not assume one body evaluation per tap. Keep side effects out of body.

Read further: Apple: State

02 · Store facts, derive output 16 / 23

One Fact One Source of Truth

  • Store independent facts once.
  • Calculate display values from those facts.
  • Avoid extra mutation paths that can be forgotten.

One source per fact does not mean one giant global object.

Read further: Apple: Managing UI state

Repair by Deriving Output
