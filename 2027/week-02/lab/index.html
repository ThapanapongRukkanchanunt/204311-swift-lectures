W02-Lab: ให้แอปตอบสนองด้วย State

ก่อนเริ่มต้น

วิดีโอ: [ลิงก์ Edpuzzle — ผู้สอนเพิ่มภายหลัง]

คุณจะสร้าง Campus Queue สำหรับจำลองจำนวนผู้รอรถรับส่ง เริ่มที่ 3 คน ปุ่ม Join เพิ่มคน ปุ่ม Leave ลดคน และข้อความเปลี่ยนเมื่อมีอย่างน้อย 5 คน แอปนี้เป็นแบบจำลองในเครื่อง ไม่ได้จองคิวจริง

[ภาพตัวอย่างแอป — ผู้สอนเพิ่มภายหลัง]

  • เชื่อม Button กับ @State และทำนายผลหลังเปลี่ยนค่า
  • แสดงเนื้อหาตามเงื่อนไขและสังเกตลำดับ event → state → UI
  • ตรวจพบและแก้ปัญหาจำนวนติดลบ

เตรียม: Mac ที่ติดตั้ง Xcode พร้อม iPhone/iPad Simulator หรือ iPad ที่ติดตั้ง Swift Playgrounds, แอป Pages/Word หรือแอปเอกสารที่ส่งออก PDF ได้ และบัญชี Canvas สำหรับดูวิดีโอและส่งงาน เคยสร้างและ Run แอปตาม Week 01 ได้แล้ว

สร้างโปรเจ็กต์ใหม่ตามภารกิจที่ 1 ไม่ต้องดาวน์โหลดไฟล์หรือใช้โปรเจ็กต์เดิม ไม่ต้องใช้บริการ cloud, API key หรือสิทธิ์กล้อง/ตำแหน่ง เลือก Simulator บน Mac จึงไม่ต้องใช้บัญชีสำหรับ signing เครื่องจริง ภาพส่งงานควรมีเฉพาะแอปหรือโค้ดที่เกี่ยวข้อง ไม่ติดรายละเอียดบัญชีหรือข้อมูลส่วนตัว

ภารกิจ

1. สร้างโปรเจ็กต์และอ่านทางเข้าของแอป 15 นาที

  1. Xcode บน Mac: สร้าง iOS App ชื่อ CampusQueueLab เลือก Interface เป็น SwiftUI, Language เป็น Swift และไม่ใช้ระบบจัดเก็บข้อมูล เลือก Simulator ที่ติดตั้งไว้แล้ว Run
  2. Swift Playgrounds บน iPad: จากหน้ารวมโปรเจ็กต์เลือกสร้าง App ใหม่ (New Playground → App หรือปุ่ม + → App ตามรุ่น) ตั้งชื่อ CampusQueueLab แล้วเปิด App Preview หรือ Run
  3. เปิดไฟล์ที่มี @main มองหา WindowGroup { ContentView() } แล้วเปิด ContentView.swift สังเกตว่า App ระบุ scene ส่วน ContentView อธิบายหน้าจอ ไม่ต้องเพิ่ม @main อีกตัว
  4. เก็บ import SwiftUI, โครง struct ContentView: View และ var body: some View ไว้ แทนเฉพาะเนื้อหาภายใน body ด้วยตัวอย่างด้านล่าง ส่วน preview ที่ท้ายไฟล์คงไว้ได้

ContentView.swift — ภายใน body

VStack(spacing: 16) {
    Text("Campus Queue")
        .font(.title)
    Text("Ready")
}
.padding()

ตรวจผล: Run แล้วเห็น Campus Queue และ Ready ถ้าไม่เห็นให้ตรวจว่า WindowGroup เปิด ContentView และแก้ error แรกก่อน ห้ามลบวงเล็บปิดของ body หรือ struct

2. เพิ่ม State และปุ่ม Join 20 นาที

ContentView.swift — ภายใน struct แต่ก่อน var body เพิ่มสองบรรทัดนี้

@State private var waiting = 3
@State private var lastEvent = "No action yet"

ContentView.swift — ใน VStack แทน Text("Ready") ด้วย

Text("Waiting: \(waiting)")
    .font(.title2)
    .accessibilityLabel("People waiting")
    .accessibilityValue("\(waiting)")

Button("Join queue") {
    let old = waiting
    waiting += 1
    lastEvent = "Join: \(old) to \(waiting)"
}

Text(lastEvent)
    .font(.caption)
  1. Run ใหม่ให้เริ่มที่ 3 คน ก่อนกดปุ่มให้ทำนายค่าหลังจากกดสองครั้ง แล้วกด Join สองครั้ง
  2. ดู Waiting และบรรทัดเหตุการณ์ล่าสุด เปรียบเทียบค่าเก่ากับค่าใหม่ บรรทัดนี้ใช้แทนหลักฐาน console ได้ทั้ง Mac และ iPad

ตรวจผล: Waiting: 5 และ Join: 4 to 5 หากตัวเลขไม่เปลี่ยน ตรวจ @State และว่าคำสั่งเพิ่มค่าอยู่ภายใน action ของ Button ไม่อยู่ใน body โดยตรง

เก็บภาพที่ 1: หน้าจอที่มี Waiting: 5 และ Join: 4 to 5 ก่อนเพิ่มเงื่อนไขในภารกิจถัดไป

lastEvent เก็บประวัติเหตุการณ์ล่าสุด จึงไม่ใช่สำเนาของจำนวนคน: เมื่อจำนวนเท่ากัน เหตุการณ์ก่อนหน้าอาจต่างกัน ส่วนข้อความสถานะคิวในภารกิจต่อไปจะคำนวณจาก waiting โดยตรง

3. แสดงสถานะตามจำนวนคน 15 นาที

ContentView.swift — ใน VStack ก่อน Button("Join queue") เพิ่มเงื่อนไขนี้

if waiting >= 5 {
    Text("Queue forming")
} else {
    Text("Seats available")
}
  1. เลือกเพิ่มสัญลักษณ์หนึ่งแบบภายในแขนง waiting >= 5: Image(systemName: "person.2.fill") หรือ Image(systemName: "bus.fill") ใส่ .accessibilityHidden(true) ต่อท้าย Image เพราะมีข้อความอธิบายอยู่แล้ว
  2. หยุดแล้ว Run ใหม่ให้กลับเป็น 3 คน ดู Seats available กด Join หนึ่งครั้งเป็น 4 แล้วยังเป็นข้อความเดิม กดอีกครั้งเป็น 5 ต้องเปลี่ยนเป็น Queue forming พร้อมสัญลักษณ์ที่เลือก

ตรวจผล: ข้อความตรงกับเงื่อนไขที่ 3, 4 และ 5 ไม่ใช้สีเพียงอย่างเดียวบอกสถานะ หากเห็นข้อความซ้ำ ตรวจว่าไม่ได้เก็บ Text("Ready") หรือข้อความสถานะเก่าไว้นอก if

เก็บภาพที่ 2: หน้าจอ Waiting: 5 พร้อม Queue forming และสัญลักษณ์ที่คุณเลือก

4. เพิ่ม Leave และจับปัญหาที่ขอบเขต 15 นาที

ขั้นนี้จงใจเริ่มด้วยกฎที่ยังมีข้อผิดพลาด เพื่อดูว่าปุ่มทำงานถูกลำดับแต่กฎข้อมูลยังผิดได้อย่างไร

ContentView.swift — ใน VStack หลังปุ่ม Join และก่อน Text(lastEvent)

Button("Leave queue") {
    let old = waiting
    waiting -= 1
    lastEvent = "Leave: \(old) to \(waiting)"
}
  1. จากจำนวนที่มีอยู่ กด Leave จนเห็น 0 แล้วทำนายว่าจะเกิดอะไรหากกดอีกครั้ง
  2. กด Leave อีกหนึ่งครั้ง สังเกตว่าตัวเลขกลายเป็น -1 แม้แอปยังรันได้ คิดว่าต้องแก้เงื่อนไขที่ปุ่มหรือเปลี่ยนกฎการคำนวณอย่างไร

เก็บภาพที่ 3: สถานะผิดพลาด Waiting: -1 และ Leave: 0 to -1 ก่อนแก้โค้ด

สังเกต: นี่คือข้อผิดพลาดของพฤติกรรม ไม่ใช่ compiler error ผู้รอไม่ควรติดลบ แต่ Swift ยังยอมให้จำนวนเต็มลดลงได้

5. ซ่อมกฎและตรวจทั้งสองเส้นทาง 15 นาที

ContentView.swift — ใน action ของ Leave แทนเฉพาะ waiting -= 1 ด้วย

waiting = max(0, waiting - 1)
  1. หยุดแล้ว Run ใหม่เพื่อเริ่มข้อมูลใหม่ที่ 3 กด Leave สามครั้งเป็น 0 แล้วกดอีกครั้ง ค่าต้องยังเป็น 0 และเหตุการณ์เป็น Leave: 0 to 0
  2. กด Join ห้าครั้งให้ถึง 5 แล้ว Leave หนึ่งครั้งให้กลับ 4 ตรวจว่าข้อความเปลี่ยนจาก Queue forming กลับ Seats available
  3. กด Leave จนเป็น 0 แล้วกดอีกครั้ง เก็บภาพสุดท้ายตามคำขอด้านล่าง
  4. ลองหมุนหน้าจอและเพิ่มขนาดข้อความจากการตั้งค่าของอุปกรณ์หรือ Simulator ตรวจว่าปุ่มและข้อความยังอ่านได้ หากพื้นที่ไม่พอ ครอบ VStack ด้วย ScrollView โดยคง state ไว้นอก body

ตรวจผล: จำนวนไม่ต่ำกว่า 0 และข้อความสะท้อนค่าทั้งขาขึ้นและขาลง หากยังติดลบ ตรวจว่าแก้ action ของ Leave และหยุด/Run ใหม่หลังแก้

เก็บภาพที่ 4: หลังซ่อมเห็น Waiting: 0, Seats available และ Leave: 0 to 0

สำหรับ Xcode อาจใส่ print(lastEvent) หลังบรรทัดแก้ lastEvent ใน action แล้วดู Debug console เพิ่มเติมได้ บน iPad ใช้บรรทัดเหตุการณ์ในแอปได้โดยไม่ต้องหา console ทั้งสองทางแสดงหลักฐานค่าเก่า → ค่าใหม่เหมือนกัน

เพิ่มเติม. เพิ่ม Reset (ไม่บังคับ) 5 นาที

เพิ่มปุ่ม Reset ให้ waiting กลับเป็น 3 และบันทึกเหตุการณ์ลง lastEvent โดยใช้ state เดิม ทดสอบจาก 0 และ 5 แล้วตรวจว่าเงื่อนไขข้อความเปลี่ยนตามเอง ไม่ต้องส่งภาพเพิ่ม

ยินดีด้วย!

คุณสร้างปุ่มที่เปลี่ยน State แสดงข้อความตามเงื่อนไข และซ่อมกฎที่ทำให้จำนวนติดลบได้แล้ว

6. รวมภาพและส่ง PDF 10 นาที

  1. เปิด Pages, Word หรือแอปเอกสารที่ใช้ได้ทั้งเครื่องของคุณ แทรกภาพที่ 1–4 ตามลำดับ ภาพละหนึ่งหน้า
  2. ใส่คำบรรยายสั้นตามนี้: 1. Join event, 2. Conditional status, 3. Negative count, 4. Fixed at zero
  3. ส่งออกเป็น PDF ชื่อ W02_รหัสนักศึกษา.pdf แล้วเปิดตรวจว่ามีครบ 4 หน้า ตัวเลขและบรรทัดเหตุการณ์อ่านชัด ภาพไม่ถูกตัด
  4. อัปโหลดไฟล์ใน Canvas Assignment ของ Week 02 ตรวจว่าไฟล์ที่ส่งเปิดได้ เก็บโปรเจ็กต์ไว้ในเครื่อง
