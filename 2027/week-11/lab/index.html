ก่อนเริ่มต้น

[ลิงก์ Edpuzzle — ผู้สอนเพิ่มภายหลัง]

เชื่อมภาพฝึกกับคำขอ Library help เพิ่มคำบรรยาย และตรวจการคงอยู่ การเปลี่ยน และการลบ โดยไม่อ่านคลังภาพทั้งหมด

[ภาพตัวอย่างแอป — ผู้สอนเพิ่มภายหลัง]

  1. Xcode / Swift Playgrounds ที่รองรับ PhotosPicker (iOS/iPadOS 16+) ใช้ภาพวัตถุจำลองขนาดเล็กกว่า 2 MB
  2. ไม่ใช้ภาพคน เอกสารจริง หรือข้อมูลสถานที่ละเอียด เตรียมภาพใน Photos ของ Simulator/iPad ล่วงหน้า
  3. ใช้ starter ใหม่ ตัวอย่างนี้เก็บ attachment เดียวของคำขอฝึก ไม่ใช่ระบบแนบหลายไฟล์ production

เตรียมโปรเจกต์

ดาวน์โหลด catch-up starter Week 11 แล้วแตกไฟล์ สร้างโปรเจกต์ SwiftUI App ใหม่ใน Xcode หรือ App ใหม่ใน Swift Playgrounds เก็บ App entry เดิมไว้ เพิ่มไฟล์ Swift ตาม README และแทนเฉพาะ ContentView.swift ของโปรเจกต์ใหม่ Run ให้ผ่านก่อนแก้ตามภารกิจ ไม่ทับโปรเจกต์เดิม ก่อนแก้เลือกภาพฝึกเล็กได้ บันทึกในเครื่องและกด Remove ได้

ภารกิจ

1. เชื่อม attachment กับคำขอ 15 นาที

  1. อ่าน fileURL และ task(id: selection) ใน starter เพื่อหาจุดที่เขียนไฟล์สำเร็จ
  2. เพิ่ม Text("Request: Library help") ก่อน picker ให้ชัดว่าภาพผูกกับคำขอใด
  3. เพิ่ม @AppStorage("requestCaption") private var caption = "" ก่อน body และ TextField("Attachment description", text: $caption) หลัง picker
  4. ใช้คำอธิบายสั้นที่บอกประโยชน์ของภาพ ไม่เก็บข้อความยาวหรือข้อมูลลับใน AppStorage

ตรวจผล / แก้ปัญหา: เห็นชื่อคำขอพร้อมคำบรรยายและภาพที่เลือก ถ้าไม่โหลดตรวจขนาดและชนิดไฟล์

เก็บภาพที่ 1: ชื่อคำขอ ภาพฝึก และคำบรรยาย

2. ตรวจบันทึกและการเปิดใหม่ 20 นาที

  1. แก้ accessibilityLabel ของ Image ให้ใช้ caption เมื่อไม่ว่าง และใช้ "Request attachment" เมื่อว่าง
  2. เลือกภาพ A แล้วรอ Saved locally ปิดและเปิดแอปใหม่ ตรวจภาพและ caption
  3. เปลี่ยน message ใน .task แรกให้บอก Restored เมื่ออ่านและ decode สำเร็จ และ No saved attachment เมื่อไม่มีไฟล์ แยก decode ไม่ได้เป็น Attachment unavailable
  4. อย่าเก็บ absolute path ลง AppStorage ให้ใช้ fileURL ที่คำนวณจาก app directory

ตรวจผล / แก้ปัญหา: เปิดใหม่เห็นภาพเดิมและ caption ถ้าเห็นเพียง caption ให้ตรวจไฟล์และการ decode ไม่สรุปว่า save สำเร็จจาก UI เดิม

เก็บภาพที่ 2: หลังเปิดใหม่เห็น Restored พร้อมภาพและคำบรรยาย

3. ยกเลิกและทดสอบ replacement 20 นาที

  1. เปิด picker แล้ว Cancel โดยไม่เลือก ภาพ A ต้องยังอยู่
  2. เลือกภาพ B ขนาดเล็กแล้วรอสำเร็จ ภาพใหม่จึงแทน A
  3. เลือกไฟล์ใหญ่เกินขอบเขตหรือภาพที่โหลดไม่ได้ ถ้ามีข้อมูลฝึกเหมาะสม ต้องมีข้อความอธิบายและไม่ทำลายภาพที่รับไว้แล้ว
  4. ตรวจโค้ดว่าเขียนไฟล์หลัง validate และ Task.checkCancellation() ไม่ clear image ก่อนโหลด

ตรวจผล / แก้ปัญหา: Cancel คงภาพเดิม และ replacement ที่ไม่ผ่านไม่อ้างว่าบันทึกสำเร็จ หากภาพเก่าหายให้หาบรรทัด clear ที่อยู่ก่อน accept

เก็บภาพที่ 3: หลัง Cancel ยังแสดงภาพที่รับไว้ก่อนหน้า

4. ลบและกู้กรณีไม่มีไฟล์ 20 นาที

  1. ใน action Remove ตั้ง caption = "" หลังลบไฟล์สำเร็จเท่านั้น รักษา catch ไว้
  2. กด Remove แล้วปิดและเปิดใหม่ ต้องเห็น No saved attachment และคำบรรยายว่าง
  3. กด Remove ซ้ำให้แอปยังใช้ได้ จากนั้นเลือกภาพใหม่ตรวจว่ากลับมาทำงานได้
  4. เพิ่มข้อความสั้นในหน้าจอว่า Stored on this device. Remove deletes the app copy. ไม่อ้างว่าลบภาพต้นฉบับจาก Photos

ตรวจผล / แก้ปัญหา: ไฟล์ที่แอปเก็บและ metadata ของ attachment ถูกเคลียร์ แต่ภาพต้นฉบับใน Photos ไม่ถูกลบ

เก็บภาพที่ 4: หลัง Remove และเปิดใหม่เห็นสถานะไม่มี attachment

เพิ่มเติม (ไม่บังคับ) · 5 นาที

ออกแบบ metadata สำหรับเสียงหรือวิดีโอหนึ่งรายการ โดยไม่โหลดไฟล์ใหญ่ทั้งก้อนและไม่ขอ permission ที่ยังไม่ได้ใช้ ไม่ต้องส่งภาพเพิ่ม

ยินดีด้วย!

คุณตรวจความต่างระหว่างภาพใน memory ไฟล์ถาวร และ metadata พร้อมการยกเลิกและลบได้แล้ว
