ตรวจ Release Candidate และนำเสนอโครงงาน

ก่อนเริ่มต้น

[ลิงก์ Edpuzzle — ผู้สอนเพิ่มภายหลัง]

ตรวจแอปที่เตรียมไว้แล้ว เก็บหลักฐาน release readiness และนำเสนอทีมละเจ็ดนาทีตามลำดับที่ผู้สอนกำหนด คาบนี้ไม่เริ่มสร้าง feature ใหม่

[ภาพตัวอย่างแอป — ผู้สอนเพิ่มภายหลัง]

  1. ก่อนคาบ ดูวิดีโอที่ผู้สอนจัดให้ เตรียม build ที่ผ่านการทดสอบ ข้อมูล demo สมมติ release notes และซ้อมการนำเสนอ
  2. เตรียมไฟล์เอกสารว่างสำหรับ PDF และอุปกรณ์ที่เปิด candidate ได้จริง พร้อมสายหรือวิธีแสดงหน้าจอที่ทดสอบแล้ว
  3. ใช้เส้นทางติดตั้งหรือสาธิตที่คุณมีสิทธิ์ใช้ ไม่ต้องซื้อสมาชิกเพื่อทำแล็บ หากยังไม่ได้ upload TestFlight/App Store ให้ระบุว่ายังไม่ได้ทำ
  4. รายงานโครงงานและเอกสารทีมส่งตามคำสั่งโครงงานแยกต่างหาก ไม่แนบเพิ่มใน PDF แล็บนี้

ภารกิจ

1. ระบุ candidate และตรวจ config 8 นาที

  1. เปิดโปรเจกต์หรือ build ที่เตรียมมา ระบุ version/build และ source revision ในบันทึกทีม
  2. ตรวจชื่อแอป endpoint permissions และข้อความ privacy ว่าตรงกับ feature จริง ไม่แสดง secret บนจอ
  3. Mac: ตรวจ candidate ที่ Run/ติดตั้งได้ตามสิทธิ์ที่มี; iPad: เปิด app playground หรือแอป candidate ที่ได้รับอนุญาตและตรวจค่าที่เครื่องมือแสดงได้ ไม่อ้างว่า archive ผ่านหากยังไม่ได้ทำ
  4. ถ้าพบ secret หรือ core flow พัง ให้ระบุเป็น blocker ไม่ซ่อนด้วยการเปลี่ยนป้ายผ่าน

ตรวจผล / แก้ปัญหา: ระบุตัวแอปที่กำลังตรวจได้และไม่เผยข้อมูลส่วนตัว ถ้า candidate ไม่พร้อมให้บันทึก limitation และ recovery ตามจริง

เก็บภาพที่ 1: หน้าจอหรือการตั้งค่าที่ระบุ candidate/version โดยไม่เห็นบัญชีหรือ secret

2. ทำ smoke test และตรวจผล 9 นาที

  1. เปิดแอปจากจุดเริ่มต้นแล้วทำ MVP flow หลักหนึ่งเส้นทางด้วยข้อมูลสมมติ
  2. ตรวจ cloud จริงและ feedback เมื่อใช้ไม่ได้ รวมถึงข้อมูลที่ต้องอยู่หลังเปิดใหม่ตาม feature ของทีม
  3. ตรวจ add-on ของตนเองหนึ่งเส้นทาง และอ่านผล automated tests ล่าสุดว่าเป็น candidate เดียวกัน
  4. หาก demo สดมีปัญหาเตรียมหลักฐานสำรองที่ระบุว่าเป็นภาพก่อนหน้า ไม่แสดงว่าเป็นการรันปัจจุบันที่ผ่าน

ตรวจผล / แก้ปัญหา: ผลที่รายงานตรงกับสิ่งที่ทดสอบจริงและมีข้อจำกัดที่อธิบายได้

เก็บภาพที่ 2: MVP หรือ add-on ที่ทดสอบใน candidate พร้อมผลลัพธ์สำคัญ

3. จัดหลักฐานและเตรียม demo 8 นาที

  1. ตรวจ release notes ว่าบอกการเปลี่ยนแปลงที่สังเกตได้หนึ่งข้อ ข้อจำกัดหนึ่งข้อ และ maintenance action พร้อมผู้รับผิดชอบ
  2. เก็บภาพที่ขอด้านล่าง จากนั้นแทรกภาพ 1–3 ลงเอกสาร PDF ที่เตรียมไว้ ภาพละหน้า ใส่คำบรรยายสั้น อ่านตรวจและเตรียม export ไว้ก่อนเริ่ม presentation block
  3. นำเสนอตามลำดับทีมที่ผู้สอนแจ้ง: เจ็ดนาทีสาธิต หนึ่งนาทีคำถาม และหนึ่งนาทีเปลี่ยนทีม โดยต้องมี release-readiness และ maintenance evidence
  4. ระหว่างทีมอื่นนำเสนอ พิจารณาว่าหลักฐานรองรับคำกล่าวอ้างใดและข้อใดยังต้องตรวจ ไม่ต้องทำรายงานเพิ่ม

ตรวจผล / แก้ปัญหา: PDF พร้อมตรวจส่งหลัง presentation และทีมมีลำดับ demo ที่แสดงหลักฐาน ไม่ใช้เวลานำเสนอเขียนโค้ดใหม่

เก็บภาพที่ 3: release notes ที่มีข้อจำกัดและ maintenance action โดยไม่มีข้อมูลลับ

ยินดีด้วย!

คุณตรวจ candidate เก็บหลักฐาน และสาธิตงานพร้อมข้อจำกัดและแนวทางบำรุงรักษาแล้ว หลังช่วงนำเสนอให้ตรวจและอัปโหลด PDF ที่เตรียมไว้

รวมภาพและส่ง PDF · 5 นาที

เรียงภาพตามนี้ ภาพละหนึ่งหน้า พร้อมคำบรรยายสั้น:

  1. 1. หน้าจอหรือการตั้งค่าที่ระบุ candidate/version โดยไม่เห็นบัญชีหรือ secret
  2. 2. MVP หรือ add-on ที่ทดสอบใน candidate พร้อมผลลัพธ์สำคัญ
  3. 3. release notes ที่มีข้อจำกัดและ maintenance action โดยไม่มีข้อมูลลับ
